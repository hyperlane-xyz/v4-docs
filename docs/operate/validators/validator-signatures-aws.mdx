---
title: "Amazon S3"
description: "Set up the default checkpoint bucket for a Hyperlane Validator."
---

Amazon S3 is the default checkpoint storage option in the Validator guide. You need an AWS IAM role or user that the Validator can use to write checkpoint files. [AWS KMS](/docs/operate/aws-kms) and [Google Cloud KMS](/docs/operate/google-cloud-kms) are separate signing options.

If your Validator uses AWS access keys, create an IAM user and set `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` in the Validator's environment. These steps also apply when you use Google Cloud KMS for checkpoint signing. [Create an IAM user](/docs/operate/aws-kms#create-an-iam-user)

## Create an S3 bucket

1. Go to AWS's S3 in the AWS console.

2. On the right, click the orange "Create Bucket" button

3. Pick an informative bucket name, such as `hyperlane-validator-signatures-${validator_name}-${chain_name}`

4. Choose a region and use that region in the checkpoint syncer settings.

5. Keep the recommended "ACLs disabled" setting for object ownership.

6. Configure public access settings so that the relayer can read your signatures

   1. Uncheck "Block all public access"
   2. Check the first two options that block access via access control lists
   3. Leave the last two options unchecked, we will be granting public read access via a bucket policy
   4. Acknowledge that these settings may result in public access to your bucket

7. The remaining default settings are fine, click the orange "Create bucket" button on the bottom

## Configure S3 bucket permissions

Grant the Validator's IAM role or user write access. Relayers read signed checkpoints without AWS credentials.

1. In IAM, copy the ARN of the role or user that runs the Validator.
2. In the S3 bucket's **Permissions** tab, edit the **Bucket policy**.
3. Paste the policy below and replace `${BUCKET_ARN}` and `${VALIDATOR_IAM_ARN}` with your own ARNs.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "${BUCKET_ARN}/*"
    },
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:ListBucket",
      "Resource": "${BUCKET_ARN}"
    },
    {
      "Effect": "Allow",
      "Principal": { "AWS": "${VALIDATOR_IAM_ARN}" },
      "Action": "s3:PutObject",
      "Resource": "${BUCKET_ARN}/*"
    }
  ]
}
```

<Tip>
  Advanced users may consider using the [S3 Terraform
  module](/docs/operate/guides/deploy-with-terraform#modules) instead to create
  the S3 bucket with the correct permissions.
</Tip>

## Configure the Validator

Add this block to your agent config and replace the example bucket and region. If Validators share a bucket, give each origin and signer a distinct folder.

```json
{
  "checkpointSyncer": {
    "type": "s3",
    "bucket": "your-validator-bucket",
    "region": "us-east-1",
    "folder": "ethereum-validator-1"
  }
}
```

Start the agent and verify checkpoint publication. [Run Validators](/docs/operate/validators/run-validators#success)
